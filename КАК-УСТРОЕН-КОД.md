# Как устроен код «Дом» — карта для защиты

Открыть любой кусок проекта и понять, что он делает и зачем. Сверху общая логика, дальше файлы.

---

## 1. Главная мысль: одна история от начала до конца

Продукт про один сценарий: **авария → пульт диспетчера → оповещение соседей по стояку → статус
жителю**. Всё остальное (счётчики, квитанция, опросы, капремонт) — вспомогательное и живёт на тех же
данных дома.

Проект — две программы и труба между ними:

- **Бэкенд** (`src/`) — «мозг». Хранит данные, проверяет, кто пришёл, считает, ходит в MAX и GigaChat.
  TypeScript, запускается через Node в Docker.
- **Мини-аппа** (`miniapp/`) — «лицо». Экраны в телефоне. React, собирается в `public/miniapp/app.js`.
- **API** — адреса `/api/v1/...`, по которым лицо спрашивает мозг.
- **Бот** — вторая «морда» того же мозга, в чате MAX. Заявки из чата и из приложения одинаковые.

Аналогия со стройкой: бэкенд — каркас и инженерные расчёты, мини-аппа — фасад и отделка, API —
трубы и провода, база (`data/db.json`) — журнал эксплуатации дома.

## 2. Что происходит, когда житель жмёт «Авария в доме»

1. Мини-аппа (`main.jsx`) отправляет фото на `/ai/scan` → GigaChat говорит «прорыв стояка» →
   категория и описание заполняются сами.
2. «Отправить» → `api.js` шлёт `POST /api/v1/requests` и прикладывает **подпись MAX** (`X-Max-Init-Data`).
3. `auth.ts` проверяет подпись и понимает, кто это. `requireMembership` находит его **прописку**:
   дом и квартира берутся отсюда, а не из того, что прислал телефон.
4. `services.ts → createRequest` пишет заявку в `store.ts` и просит бота написать жителю «заявка принята».
5. Пульт диспетчера раз в 5 секунд спрашивает `/dispatch/state` — авария появляется на схеме подъезда
   (`twin.ts` считает этаж и стояк).
6. Диспетчер жмёт «Оповестить» → `dispatch.ts` находит всех, кто прописан в квартирах выше/ниже по
   стояку, и бот пишет им в MAX.
7. Диспетчер жмёт «В работу» / «Устранено» → `PATCH /requests/:id` → `services.ts → changeStatus`
   пишет историю и отправляет жителю сообщение.

Разберёшься в этой цепочке — поймёшь весь проект.

## 3. Бэкенд — папка `src/`

### `server.ts` — рубильник
Поднимает веб-сервер, отдаёт мини-аппу, подключает API, запускает бота. Тут же страница
`/poster/<fiasId>` — листовка с QR для подъезда. Ставит защитные заголовки, превращает кривой JSON
в понятную ошибку 400.

### `config.ts` — все настройки
Читает `.env` и `config/*.json`: реестр домов, тарифы, базу знаний. `tariffsFor(город, дата)` сам
выбирает период тарифов (в 2026 году индексация 1 октября). Здесь же тестовые жители для автопроверки.
**Токенов в коде нет — только в `.env`.**

### `net.ts` — безопасный выход в интернет
MAX и GigaChat используют сертификаты НУЦ Минцифры, которых нет в Node. Раньше проверку TLS просто
выключали на весь процесс — это дыра. Теперь к стандартным сертификатам добавлены два публичных
российских (`certs/russian-trusted-ca.pem`), и проверка работает полностью.

### `auth.ts` — охранник на входе
Кто прислал запрос, три способа:
- **подпись MAX** (`X-Max-Init-Data`): алгоритм из документации MAX — ключ из токена бота через
  `"WebAppData"`, проверка `hash` и свежести `auth_date` (1 час);
- **тестовый ключ** (`X-Test-Key`): только два заранее прописанных тестовых жителя, никогда не диспетчер;
- **dev** (`X-Debug-User`): только при локальном запуске `AUTH_DEV=1`.

Там же роли: диспетчер = ввёл код своей УК (`/staff/login`, коды в `STAFF_CODES`) и видит только дома этой УК.

### `store.ts` — память
Заявки (с историей статусов), показания, опросы, прописки, сотрудники УК — в `data/db.json`.
Запись атомарная (через временный файл), при остановке контейнера база дописывается. Важные правила:
- `castVote` — **один голос с квартиры** и только в опросе своего дома;
- `lastMeters` — только свои показания;
- `residentsOf` — кто прописан в квартире (адресаты оповещения);
- при загрузке старая база мигрирует сама.

### `services.ts` — бизнес-логика
Одна и та же для приложения и бота: создать заявку, сменить статус (с проверкой, что переход
допустим: закрытую заявку нельзя «вернуть в работу»), сохранить показания.

### `api.ts` — телефонная книга адресов
Все адреса API. Главное: `/requests` (создать, список, `PATCH` статус), `/dispatch/*` (пульт),
`/attach` (прописка), `/me` (кто я и какая роль). Плюс ограничение частоты запросов.

### `dispatch.ts` — пульт диспетчера
Аварии конкретного дома, зона риска по стояку, оповещение соседей по пропискам.

### `twin.ts` — геометрия подъезда
Чистая математика: по номеру квартиры — подъезд, этаж и стояк; соседи на этаж выше и ниже.

### `maxbot.ts` — бот в MAX
Long polling, кнопки. Приложение открывается кнопкой `open_app` (мини-аппа привязана к боту). Знает дом жителя из прописки, поэтому телефоны и капремонт у каждого свои.
«🚨 Авария в доме» → следующее сообщение становится аварийной заявкой. «ХВС 123 ГВС 45» → показания
реально сохраняются с суммой. Все сообщения идут по `user_id`.

### `gigachat.ts`, `vision.ts` — ИИ
Ответы строго по базе знаний дома; распознавание фото с проверкой ответа модели кодом. Нет ключа —
отвечаем из базы знаний, сканер в демо с пометкой.

### `categories.ts`
Категории заявок и сроки реакции (авария — 30 минут).

## 4. Мини-аппа — `miniapp/`

- `index.html` — каркас, подключает **MAX Bridge** (`max-web-app.js`).
- `src/main.jsx` — все экраны. Главная начинается с большой кнопки «Авария в доме», ниже статус
  последней заявки, остальное в «Других сервисах». Вкладки: Главная, Заявки, Опросы, О доме.
  Понятные ошибки и кнопка «Попробовать снова». Нативная кнопка «Назад», вибро-отклик и шеринг в MAX
  работают внутри MAX (`isInsideMax`); в обычном браузере при локальном запуске — кнопка «Назад» в шапке
  и системное «Поделиться».
- `src/api.js` — связной с сервером: подпись MAX, статусы заявок.
- `src/dispatch.jsx` — пульт: схема подъезда, оповещение, кнопки статусов, открытые заявки, QR-листовка.
- `src/scanner.jsx` — камера и распознавание фото.
- `styles.css`, `wow.css` — внешний вид.

> `miniapp/src/` — исходники. Собираются `npm run build:app` в `public/miniapp/app.js`.

## 5. Данные — `config/`

- `house.json` — дом по умолчанию; `houses.json` — остальные (СПб и Казань). Новый дом = новая запись.
- `tariffs.json` — тарифы по городам и периодам с реквизитами документов; модельные помечены `model`.
- `kb.json` — база знаний с основанием к каждому ответу.

---

## 6. Запуск и проверки

- `Dockerfile`, `compose.yaml` — `docker compose up --build`, одна команда. Бот по умолчанию выключен,
  чтобы чужой запуск не отбирал сообщения у живого стенда.
- `scripts/api-check.mjs` — 40 проверок API (сценарий и доступы), `scripts/auth-check.ts` — подпись MAX,
  `scripts/smoke-ui.mjs` — рендер мини-аппы, `scripts/watchdog.sh` — сторож стенда.
- `README.md` — для жюри, `RUNBOOK.md` — эксплуатация стенда, `openapi.yaml` и `DATA-API.yaml` — контракт API.

## 7. «Хочу поменять X — куда лезть»

| Задача | Файл |
|---|---|
| Добавить дом или город | `config/houses.json`, `config/tariffs.json` |
| Тексты ответов бота на вопросы | `config/kb.json` |
| Сроки реакции (SLA) | `src/categories.ts` |
| Правила статусов заявки | `src/services.ts` → `TRANSITIONS` |
| Кто что может | `src/auth.ts` |
| Текст оповещения соседям | `src/dispatch.ts` → `noticeText` |
| Кнопки и тексты бота | `src/maxbot.ts` |
| Экраны мини-аппы | `miniapp/src/main.jsx` |
| Токены и ключи | `.env` на сервере |

## 8. Что уметь объяснить у доски

1. **Один сценарий от начала до конца.** Авария с фото → пульт → соседи по стояку → статус жителю.
   Каждый шаг виден жителю в MAX.
2. **Доступ по прописке.** Дом и квартира не приходят из телефона, их знает сервер. Поэтому нельзя
   подать заявку за чужую квартиру, голосовать в чужом доме или читать чужие показания.
3. **Масштаб через конфиг.** Новый дом или город — строка в `config/`, код не меняется. Казань
   работает рядом с Петербургом с другими тарифами и УК.
4. **Честность данных.** Тарифы с реквизитами, модельные значения подписаны, ИИ отвечает только по
   базе знаний, демо-режим всегда помечен.
